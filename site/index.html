UNDERLEAF

Underleaf is an educational exploration game about learning to read a cloud forest. The player follows signals that ordinary sight misses, runs a controlled habitat comparison, and cares for one butterfly from egg to adult while the notebook turns those actions into a record of evidence.

The project

A small game built around observation

I wanted the player’s progress to come from understanding a living system rather than collecting objects or clearing levels. Underleaf begins with a moving line of leafcutter ants and gradually introduces chemical trails, plant-borne vibration, ultraviolet contrast, ultrasound, and polarized light as translated ways of perceiving the same forest. Each view changes what information is available and leads to a new ecological question.

The central investigation asks the player to compare a sheltered patch with an open one. Both begin equally wet, the player observes them over the same interval, changes cover in only one location, and repeats the comparison. The game records the result without treating a prediction as a grade, then carries that reasoning into a butterfly life cycle that gives the tutorial a concrete emotional ending.

Engineering

What I designed and implemented

Simulation and state

The forest tracks local habitat conditions, seasonal moisture, gated sensory discoveries, a compressed life cycle, and a repeatable ecological experiment. Versioned saves migrate older forests while preserving observations and study evidence.

Procedural presentation

The forest, insects, field plates, weather, and sensory cues are drawn in code instead of assembled from a conventional sprite pack. A custom interface keeps the diorama and field notebook visually coherent across the native and browser builds.

Tutorial architecture

A persistent chapter guide exposes the current goal, next action, and reason it matters. Tutorial time advances only through deliberate actions, so reading cannot silently consume a life stage, while completed players can continue in a less constrained simulation.

Delivery and verification

Automated suites exercise ecology, interface behavior, the comparison study, saving, migration, and the full tutorial path. GitHub Actions publishes a WebAssembly build to Pages and a universal macOS release with checksums from version tags.

Technical decisions

Constraints shaped the design

The browser and desktop editions share one Godot project, but their delivery environments are different. The web build uses a single-threaded export for broader browser compatibility, bundles its own licensed fonts, and stores progress in the browser. The macOS package contains Apple Silicon and Intel executables and keeps its save outside the app bundle, so replacing the application does not erase a player’s forest.

The educational layer also required careful boundaries. Sensory modes are explicitly described as translations for a human player, habitat percentages and development time are labeled as game abstractions, and each species page separates supported natural history from provisional placement or fictionalized mechanics. The shelter trial supports a relationship inside the model; it does not claim to prove an animal’s preference.

Current status

This is a focused tutorial build rather than a finished commercial release. Scientific review, broader novice playtesting, Intel runtime testing, richer accessibility support, and Apple notarization remain open work. The source, design document, tests, and release workflows are public so the project can be evaluated as an engineering artifact as well as played as a demo.
